# Handoff: mismatches found during B-005b (Backend -> Auditor)

From: Backend/Integrations. To: Auditor. Date: 2026-11-04. Nothing was worked around in code; all are untouched. Line numbers are on `main` (`d866372`).

1. **Runbook 0.2 and `preflight` output are wrong for a Vercel preview.** They say that outside production the webhook is processed inline without QStash and that unset Redis means in-memory limits. A Vercel Preview runs with `NODE_ENV=production`, where the webhook throws (`src/app/api/payment/webhook/route.ts:677`) and the rate limiter throws (`src/lib/rate-limit.ts:51`). The local text is correct for a local run. The preview section covers it; `scripts/safepay-sandbox-validation.mjs` still prints "processed inline" / "held in process memory" when those variables are unset locally, which is misleading when used for a preview.
2. **Inconsistent preview handling across providers.** `sendEmail` uses `isProductionDeployment()` (so a preview skips sending without a key, `src/lib/email.ts:36-41`). `sendSms` uses `NODE_ENV` (so a preview without Twilio variables returns failure, `src/lib/sms.ts:93-96`). Rate limits, CSRF, app URL and upload also use `NODE_ENV`. `src/lib/env-validation.ts:216` and `src/lib/deployment-env.ts` document the intent to treat Preview separately; it is applied to some modules only.
3. **Task text says "separate Redis or prefix".** The rate-limit prefix is fixed (`src/lib/rate-limit.ts:76`, `hostello:ratelimit`) and not configurable, so only a separate Redis database isolates preview from production. Key names in `src/lib/auth/token-version-cache.ts` were not checked.
4. **No code-level recipient guard on preview.** Nothing in `src/` restricts email or SMS recipients on a non-production deployment; test-only recipients are enforced only by data hygiene. (Email is skipped on Preview when `RESEND_API_KEY` is unset.)
5. **The deployed commit cannot be confirmed from the app.** Nothing in `src/` reads `VERCEL_GIT_COMMIT_SHA`; the Vercel dashboard is the only source.
6. **Branch layout vs. the instruction "built from main".** `main` contains the B-001 merge commit `0d4710e`; `origin/preview` contains the code commit `048db53` but not the merge commit, and `main` has 37 commits not on `preview`. A Vercel deployment of the Production branch is a Production deployment (live variables), not a Preview. Which branch Vercel treats as Production cannot be seen from the repo.
7. **Deployment Protection and QStash.** Upstash's bypass is a request header. The app's QStash publish passes no headers (`route.ts:664-669`), so the bypass cannot work without a code change.
8. **Pre-existing:** `node scripts/check-docs.mjs` reports a broken link in `docs/API-MASTERY-GUIDE.md` into `node_modules/next/dist/docs/...` when dependencies are not installed. Same on untouched `main`.
9. **Cron routes:** `cancel-abandoned-payments` sets `status=CANCELLED, paymentStatus=FAILED` and restores room places (`route.ts:47-66`); confirms audit row 11's path for late payments. `expire-unanswered-bookings` starts refunds (audit E-1 is still accurate).
